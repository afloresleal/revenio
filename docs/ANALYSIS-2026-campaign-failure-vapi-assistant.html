🚨 Análisis: Campaña Purifika - Transfer No Funciona

Problema Reportado

"Entra la llamada, responde el agente Vapi y hace el transfer... después de esto no pasa nada pero debería enlazar con un agente."

📊 Análisis de Logs (990 eventos)

Distribución de EndedReasons

silence-timed-out: 44.4% customer-did-not-answer: 22.2% customer-ended-call: 22.2% voicemail: 11.1%

🎯 Hallazgo Principal

El transfer NUNCA se está ejecutando

transfer-destination-request eventos recibidos: 0 transferAttempted: false hadTransferredAt: false endedReasonIndicatesTransfer: false

Conclusión: Vapi NO está llamando al webhook de transfer. El assistant NO está ejecutando el tool transferCall.

🔍 Causa Raíz Identificada

Problema 1: Voicemail Detection Bloqueando FirstMessage

44.4% de llamadas terminan con "silence-timed-out"

Esto ocurre cuando:

  1. Cliente contesta el teléfono
  2. Vapi inicia detección de buzón (espera hasta 20 segundos)
  3. Durante la detección, el assistant NO habla
  4. Si la detección tarda >10 segundos, se llega al timeout de silencio (30 seg)
  5. Llamada termina sin que el assistant haya dicho nada

Configuración actual:

"voicemailDetection": { "provider": "vapi", "backoffPlan": { "maxRetries": 6, "startAtSeconds": 2, "frequencySeconds": 2.5 }, "beepMaxAwaitSeconds": 20 ← Espera hasta 20 segundos } "silenceTimeoutSeconds": 30 ← Timeout a los 30 segundos

El problema: Solo hay 10 segundos de margen entre el máximo de detección (20s) y el timeout de silencio (30s).

Problema 2: Assistant No Ejecuta transferCall

Prompt del assistant:

If you detect voicemail, an answering machine, or a recorded greeting from the customer, stop speaking immediately and end the call. Do not execute transferCall. If a human answers, deliver the first message in Spanish. Immediately after the first message is fully spoken, execute transferCall. Do not wait for any response.

Problema identificado:

  • El prompt depende de que Vapi detecte correctamente si es humano o buzón
  • Si la detección falla o es incorrecta, el assistant se confunde
  • El assistant puede pensar que es buzón cuando en realidad es humano
  • Resultado: NO ejecuta transferCall

✅ Soluciones Propuestas

Opción 1: Reducir beepMaxAwaitSeconds (RECOMENDADO - Fix Rápido)

Cambio en Vapi Dashboard:

"voicemailDetection": { "provider": "vapi", "backoffPlan": { "maxRetries": 6, "startAtSeconds": 2, "frequencySeconds": 2.5 }, "beepMaxAwaitSeconds": 10 ← Reducir de 20 a 10 segundos }

Beneficios:

  • Reduce el tiempo de espera de detección a la mitad
  • Deja 20 segundos de margen antes del silence timeout
  • El assistant tiene más tiempo para hablar y ejecutar transferCall
  • Fix inmediato, sin cambios de código

Riesgo: Puede aumentar ligeramente los falsos positivos de voicemail detection.

Opción 2: Aumentar silenceTimeoutSeconds

Cambio en Vapi Dashboard:

"silenceTimeoutSeconds": 45 ← Aumentar de 30 a 45 segundos

Beneficios:

  • Da más tiempo para que complete la detección de voicemail
  • Permite que el assistant hable incluso si la detección tarda
  • Reduce los timeouts prematuros

Riesgo: Las llamadas con humanos que no responden durarán más (45 seg en vez de 30).

Opción 3: Deshabilitar Voicemail Detection (Temporal para Debug)

Cambio en Vapi Dashboard:

// Comentar o remover voicemailDetection temporalmente // "voicemailDetection": { ... }

Objetivo: Verificar si el problema es la voicemail detection.

Proceso:

  1. Deshabilitar voicemail detection
  2. Hacer 10 llamadas de prueba
  3. Verificar si el assistant habla y ejecuta transferCall
  4. Si funciona, confirma que el problema es la voicemail detection

⚠️ ADVERTENCIA: Esto hará que se dejen mensajes en buzones de voz. Solo para debug, no para producción.

Opción 4: Modificar Prompt del Assistant

Problema actual: El prompt usa lógica condicional basada en detección de voicemail.

Nuevo prompt sugerido:

You are a virtual assistant for a Real Estate company. Your task: 1. Wait for the customer to say "hello" or similar greeting 2. Deliver the first message in Spanish 3. Immediately execute transferCall after finishing the first message 4. Do not wait for any response after executing transferCall If you detect the call was answered by voicemail or an answering machine: - Do not speak - End the call immediately - Do not execute transferCall

Cambios clave:

  • Instrucciones más claras y directas
  • Espera señal del cliente ("hello") antes de hablar
  • Instrucción de voicemail al final (menor prioridad)

🎯 Resumen Ejecutivo

Problema: El transfer NO se ejecuta porque la voicemail detection está bloqueando al assistant.

Síntoma: 44% de llamadas terminan con silence-timed-out (30 seg de silencio).

Causa: Voicemail detection espera hasta 20 segundos, dejando solo 10 segundos antes del timeout.

Fix rápido: Reducir beepMaxAwaitSeconds de 20 a 10 y aumentar silenceTimeoutSeconds de 30 a 45.

Tiempo estimado: 3 minutos para aplicar cambios + 15 minutos de pruebas.
